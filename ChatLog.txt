The real-world truth:

The PostgreSQL vs MySQL debate is largely academic for a project of this scale. Both will handle Lydia's data requirements easily, and familiarity wins when you're doing this as a favor for a friend's nonprofit.

MySQL advantages for your situation:

You already know it — faster development
SQLAlchemy supports it just as well as PostgreSQL
Excellent Docker image, well documented
Plenty of hosting options if you ever move off the VM
Where PostgreSQL genuinely wins:

More advanced JSON/array data types
Better full-text search
Stronger standards compliance
Tends to be the default in most FastAPI tutorials you'll find
Practical suggestion:

Since you're using SQLAlchemy as your ORM, you're largely abstracted away from the raw SQL differences anyway. You'd rarely write raw MySQL-specific queries — SQLAlchemy handles most of it for you.

One thing to know:

If you do go MySQL, use the mysqlclient or PyMySQL driver with SQLAlchemy. The connection string just changes slightly from PostgreSQL but everything else stays the same.

Bottom line — use MySQL, get the project built, and don't spend energy learning a new database when the stack is already new enough. You can always migrate later if a compelling reason emerges.
